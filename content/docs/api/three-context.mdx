`ThreeContext` is the single runtime object for a [`ThreeStart`](/docs/api/three-start) instance. It holds the renderer, the active scene, named `scenes` map, camera, animation loop, timer, and event bus. Extra scenes: [Scenes](/docs/core-guides/scenes).

You don't construct `ThreeContext` directly — it's created automatically inside [`ThreeStart`](/docs/api/three-start) and exposed via its [`ctx`](/docs/api/three-start#properties) field.

<Callout type="info">
  Every [`Object3DBehaviour`](/docs/api/object3d-behaviour) and [`ContextModule`](/docs/api/context-module) instance has access to the same context via `this.ctx`.
</Callout>

## Events

`ThreeContext` extends [`TypedEmitter`](/docs/api/typed-emitter) and acts as the central **event bus** of the runtime — subscribe via `ctx.on(...)`, unsubscribe via `ctx.off(...)`. Events are typed by `ThreeContextEventMap` below.

<Callout type="info">
  Listeners are isolated: one that throws (including the `onUpdate` / `onBeforeRender` / `onAfterRender` of components and modules, which are ctx listeners under the hood) is reported through `Error` and the remaining listeners still run. See [Errors in event methods](/docs/core-guides/lifecycle#errors-in-event-methods).
</Callout>
